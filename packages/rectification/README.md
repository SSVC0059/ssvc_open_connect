# @ssvc/rectification

Единая модель расчёта ректификации OpenConnect. Один исходник — три потребителя:

| Потребитель | Как использует |
|---|---|
| Интерфейс (`interface/`) | Vite импортирует `src/index.js`; калькулятор и редактор профилей |
| MCP-сервер (`mcp/`) | `oc_calculate_plan`; esbuild включает модель в `dist` |
| Документация (`docs/calculator/`) | собирается из интерфейса тем же `build:calculator` |

## Почему без сборки

Пакет — чистый ESM без зависимостей и без шага сборки. Поэтому интерфейс, MCP и
документация исполняют **один и тот же файл**, а не три его копии. Типы — в
`src/index.d.ts`.

## Проверка

```bash
node --test packages/rectification/test/model.test.js
```

Тесты — единственный источник истины для математики. Интерфейс и MCP проверяют
только интеграцию: что пакет подключён и возвращает те же числа.

Полная проверка перед релизом:

```bash
node --test packages/rectification/test/model.test.js   # математика
cd interface && npm run build:calculator && npm run test:run
cd ../mcp && npm test && npm run build
```

## Границы

- Модель ничего не знает про устройство, REST, MQTT и MCP.
- `calculateProcess` не мутирует входной профиль.
- Расчёт идеализирован (теплопотери, насадка, реальная мощность не учитываются);
  это порядок величин и согласованность параметров, а не гарантия процесса.
