# API Журналов ректификаций

Журналы ректификаций — это CSV-файлы с историей процессов, которые хранятся на контроллере SSVC0059_V2. Скачивание журналов поддерживается начиная с **UART API v1.10** ([спецификация](../../ssvc_uart_api_docs.md)). На время передачи контроллер приостанавливает регулярную телеметрию и передаёт файл блоками по 600 байт (Base64).

---

## Получение списка журналов

Запрашивает у контроллера список доступных CSV-файлов.

**Эндпоинт:** `GET /rest/logs`
**Метод:** `GET`
**Аутентификация:** Требуется

### Пример запроса (curl)

```bash
curl -X GET http://DEVICE_IP/rest/logs \
     -H "Authorization: Bearer YOUR_AUTH_TOKEN"
```

### Ответы
*   **`200 OK`**: Текущее состояние передачи. Поле `files` присутствует только когда контроллер уже прислал список.
    ```json
    {
      "status": "list",
      "total": 0,
      "received": 0,
      "files": ["15.CSV", "16.CSV", "17.CSV"]
    }
    ```
*   **`409 Conflict`**: Контроллер не поддерживает GET_LOG (версия API ниже 1.10).
    ```json
    {"error": "api_version_unsupported"}
    ```

## Скачивание журнала по номеру процесса

Запускает скачивание выбранного журнала. Идентификатор процесса — целое положительное число из имени файла без расширения (например, `15` для файла `15.CSV`).

**Эндпоинт:** `GET /rest/logs/{processId}`
**Метод:** `GET`
**Аутентификация:** Требуется

### Параметры URL
*   `processId` (int) — номер процесса; должен быть положительным целым числом.

### Пример запроса (curl)

```bash
curl -X GET http://DEVICE_IP/rest/logs/15 \
     -H "Authorization: Bearer YOUR_AUTH_TOKEN" \
     --output 15.CSV
```

### Ответы
*   **`200 OK`**: Журнал полностью скачан. В теле — CSV-файл (`Content-Type: text/csv`), имя файла в заголовке `Content-Disposition: attachment; filename="15.CSV"`.
*   **`202 Accepted`**: Идёт передача. В теле — текущий прогресс:
    ```json
    {
      "status": "receiving",
      "total": 335,
      "received": 120
    }
    ```
    На этапе `error` ответ содержит поле `error` с кодом (`err_num`, `err_mnt`, `err_nf`, `err_int`, `timeout`).
*   **`400 Bad Request`**: Номер процесса невалиден (не число, ≤ 0 или превышает диапазон int).
    ```json
    {"error": "invalid_process_id"}
    ```
*   **`409 Conflict`**: Уже идёт передача другого журнала, либо версия API контроллера ниже 1.10.
    ```json
    {"error": "log_transfer_busy"}
    ```
    или
    ```json
    {"error": "api_version_unsupported"}
    ```

## Отмена передачи

Сбрасывает локальное состояние передачи на OpenConnect. Если в этот момент контроллер ещё досылает чанки, они игнорируются; телеметрия на контроллере возобновляется автоматически после отправки всего файла или пакета ошибки.

**Эндпоинт:** `DELETE /rest/logs`
**Метод:** `DELETE`
**Аутентификация:** Требуется

### Пример запроса (curl)

```bash
curl -X DELETE http://DEVICE_IP/rest/logs \
     -H "Authorization: Bearer YOUR_AUTH_TOKEN"
```

### Ответы
*   **`200 OK`**: Состояние передачи сброшено.
    ```json
    {"status": "idle"}
    ```

## Ограничения и ошибки

| Код | Источник | Значение |
|-----|----------|----------|
| `invalid_process_id` | OpenConnect | Номер процесса не прошёл валидацию |
| `api_version_unsupported` | OpenConnect | Контроллер не поддерживает GET_LOG (нужна API ≥ 1.10) |
| `log_transfer_busy` | OpenConnect | Уже идёт передача другого журнала |
| `err_num` | контроллер | неверный номер процесса |
| `err_mnt` | контроллер | ошибка монтирования файловой системы |
| `err_nf`  | контроллер | файл не найден |
| `err_int` | контроллер | внутренняя ошибка передачи |
| `timeout` | OpenConnect | новые пакеты не приходили дольше 10 с — передача считается зависшей |

---

## Условия выполнения

*   Контроллер обрабатывает `GET_LOG` только в **дежурном режиме** (`stage == waiting`).
*   Время передачи ограничено таймаутом `TRANSFER_TIMEOUT_MS = 10000` мс (отсутствие новых чанков дольше этого интервала → `ERROR / timeout`).
*   Суммарный размер файла не должен превышать 512 КБ; чанк больше 600 байт → `invalid_data`.
