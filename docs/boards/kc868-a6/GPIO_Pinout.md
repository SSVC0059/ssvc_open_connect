## SSVC по RS485

На стороне **SSVC** — UART TTL и внешний преобразователь **RS485↔TTL**; на стороне платы — трансивер с автонаправлением. В прошивке — обычный асинхронный UART на **GPIO17 (TX)** / **GPIO18 (RX)**, без `uart_set_mode(RS485)` и без DE/RE на MCU.

Параметры задаются в `platformio.ini` (`SSVC_OPEN_CONNECT_UART_TX` / `RX`).

## Датчики уровня XKC-25 (GPIO или входной PCF8574)

Датчики XKC-25-NPN подключаются к любому свободному GPIO **или** к сухому контакту на входном расширителе **PCF8574 по адресу 0x22** (I²C). Выбор источника — в веб-UI (настройки оборудования → «Датчики уровня (XKC-25)»): «GPIO (нативный пин)» либо «PCF8574 (I²C, сухой контакт)» с выбором бита P0..P7.

- Адрес входного расширителя по умолчанию — `SSVC_XKC25_PCF8574_INPUT_ADDR` (0x22); **он не должен совпадать с адресом реле (0x24)**: `Pcf8574Input` пишет `0xFF` в свой чип, и тот же чип занят выходами реле (`RelayPortCoordinator`).
- Для входа через PCF8574 внешняя подтяжка не нужна: расширитель подтягивает линию к 3.3 В. Выход датчика — открытый коллектор (NPN), т.е. замыкает линию на землю.
- Нативный GPIO по-прежнему требует внешнего резистора (к 3.3 В для NPN, к земле для PNP); прошивка линию не тянет.
- Сбой чтения по I²C — не уровень: датчик покажет «нет данных» (`rawLevel = -1`), а `/rest/oc/hardware-faults` — `I2C_NACK` с ролью `pcf8574_in`.

## Электрика входов (по схеме)

Разбор `KC868-A6-schematic.pdf` + данных KinCony (ESPHome, форум):

**6 «сухих контактов» (цифровые входы, схема — `INPUT_D1..D6`, на плате/в док. KinCony — `DI1..DI6`):**

- На каждый вход — оптопара **EL357** (U15..U20) — гальваническая развязка.
- Анод светодиода оптопары подключён к внутренней шине **+12 В** платы; катод — через резистор **2 кОм** (R38..R43) на клемму входа; узел катода подтянут к +12 В через **100 кОм** (R25..R30).
- Выход оптопары: эмиттер → GND, коллектор → входной расширитель **PCF8574 (U3, 0x22)**, биты **P0..P5 = вход 1..6**, с подтяжкой **4.7 кОм** к 3.3 В.
- **Срабатывание — замыкание клеммы входа на GND платы** (общий провод входов — это +12 В платы, а не «сухая» земля). Открытая клемма при этом читается как **~11–12 В** — это нормальный режим, а не неисправность.
- Полярность логики: покой (светодиод оптопары погашен) → линия подтянута к 3.3 В → бит = 1; замыкание на GND → светодиод горит → коллектор тянет линию к 0 → бит = 0. Отсюда `inverted: true` в ESPHome и `activeLow` по умолчанию в прошивке.

**4 аналоговых входа A1..A4 — это НЕ сухие контакты:**

- Отдельный тракт `INPUT_AA1..AA4`: делитель **5.1 кОм / 10 кОм**, диоды **BAT54S**, изолирующий усилитель; диапазон **0–5 В** (на части ревизий A3/A4 — 4–20 мА, резистором).
- Идут на **АЦП** (A6v3: GPIO 4/5/6/7; классическая A6: GPIO 36/39/34/35). Клемм A5/A6 нет.
- **Прошивка АЦП не опрашивает вообще**, поэтому замыкание A1..A4 на GND не даёт ни строк в логе, ни реакции XKC-25. Вход датчика нужно выбирать среди `DI1..DI6` (= биты P0..P5 расширителя 0x22).

**Подключение XKC-25-NPN к сухому контакту:** OUT (открытый коллектор) → `DIx`, GND датчика → **GND платы**, питание датчика (5–12 В) → отдельный источник (или +12 В платы). Внешняя подтяжка не нужна — линию тянет расширитель.

**Диагностика:** в логе `Xkc25Sensor` при источнике PCF8574 печатается весь байт порта (`port=0xNN`) раз в 5 с. При всех разомкнутых входах `port` ≈ `0xFF` (все биты подтянуты к 3.3 В); замыкание `DI1` даёт `0xFE`. Если `port` стоит на `0x00`/не меняется при замыкании — регистр расширителя не переведён в режим входов (или адрес/бит не тот).

## Алерты и реле (PinOut / AlarmMonitor)

При `PINOUT_USE_GPIO=0` уровни **DANGEROUS** / **CRITICAL** идут на выходы через **PCF8574** на I2C: адрес и биты задаются макросами `SSVC_RELAY_PCF8574_*` в сборке (на этой плате по умолчанию адрес **0x24**, биты **0** и **1**, active-LOW на линии). Другая разводка или второй расширитель — другие значения макросов / второй порт в коде. Шина — через `I2CBusSubsystem`; при пустой шине или ошибке записи — `AlarmMonitor::raiseHardwareFault`. Подробнее: [I2C_devices.md](I2C_devices.md).

При `PINOUT_USE_GPIO=1` используются только **GPIO** (`SSVC_PINOUT_ALARM_GPIO_DANGEROUS` / `CRITICAL` в `SsvcConnector.h` или `-D` в env); этот путь **не** использует PCF8574 и задаётся отдельно от I2C-реле.
