# Настройка

Вся конфигурация — переменные окружения. Если в рабочем каталоге процесса есть `.env`, он читается при
старте и **не перетирает** уже заданные переменные. Секреты хранятся только в памяти и не пишутся в логи.

Минимальный `.env`:

```dotenv
SSVC_DEVICE_URL=http://192.168.1.42
SSVC_USER=admin
SSVC_PASSWORD=пароль
SSVC_MCP_TOKEN=токен
```

Токен: `openssl rand -hex 32`.

## Контроллер

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SSVC_DEVICE_URL` | — (обязательна) | Базовый URL без завершающего слэша, например `http://192.168.1.42`. Прошивка слушает только HTTP. |
| `SSVC_USER` | — (обязательна) | Пользователь контроллера. Нужен `admin`: телеметрия и датчики доступны только ему. |
| `SSVC_PASSWORD` | — (обязательна для HTTP) | Пароль контроллера. В stdio-режиме необязательна: при выключенной на прошивке авторизации запросы идут анонимно. |
| `SSVC_DEVICE_TIMEOUT_MS` | `10000` | Таймаут одного запроса к контроллеру, 100…600000 мс. Скачивание журнала/файла имеет отдельный бюджет. |

## Доступ клиентов

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SSVC_MCP_TOKEN` | — (обязательна для HTTP) | Bearer-токен клиентов MCP. Без него HTTP-сервер не стартует; в stdio-режиме не нужен. |
| `SSVC_MCP_BIND` | `127.0.0.1` | Адрес прослушивания: `127.0.0.1` — только локально, `0.0.0.0` — вся сеть. |
| `SSVC_MCP_PORT` | `8080` | Порт HTTP. |
| `SSVC_MCP_ALLOWED_HOSTS` | пусто | Список допустимых `Host` через запятую (защита от DNS-rebinding). Пусто = localhost/127.0.0.1/[::1] и адрес из `SSVC_MCP_BIND`. При `0.0.0.0` укажите адреса явно. |
| `SSVC_MCP_ALLOWED_CIDRS` | `private` | Кто может подключаться: CIDR через запятую; `private` = RFC1918 + петлевые адреса. |
| `SSVC_MCP_MAX_SESSIONS` | `32` | Максимум одновременных сессий. |
| `SSVC_MCP_IDLE_MS` | `1800000` | Закрытие простаивающей сессии, мс (30 минут). |
| `SSVC_MCP_TLS_CERT` / `SSVC_MCP_TLS_KEY` | пусто | Встроенный TLS (нужны оба файла). Пусто — работа за TLS-прокси. |

## Политика и наблюдаемость

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SSVC_ALLOW_DESTRUCTIVE` | `0` | Разрешить операции риска 3 (`oc_restart`, `oc_profile_delete`, `oc_file_delete`). `0` — они возвращают `disabled_by_policy`. |
| `SSVC_RAW_LOG` | `off` | Запись сырых обменов: `off`, `errors`, `all`. Только для отладки: содержит данные контроллера. |
| `SSVC_RAW_LOG_DIR` | `./logs/raw` | Каталог сырых логов. |
| `SSVC_RAW_LOG_MAX_MB` | `50` | Предел объёма сырых логов, МБ (старые файлы удаляются). |
| `SSVC_AUDIT_PATH` | `./logs/audit.jsonl` | Журнал аудита опасных операций (JSONL, только добавление). |
| `SSVC_LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error`, `silent`. |

## Безопасность

- Сервер не стартует без `SSVC_MCP_TOKEN` — «открытый порт без токена» исключён.
- Разрушительные операции выключены по умолчанию и требуют одновременно: разрешения
  `SSVC_ALLOW_DESTRUCTIVE=1`, `confirm:true` и непустого `reason` в вызове; всё пишется в аудит.
- Токен и пароль контроллера не попадают в ответы инструментов и в логи.
- Наружу — только HTTPS через reverse-proxy: встроенный TLS есть, но сертификаты удобнее держать в
  прокси ([reverse-proxy](../develop/reverse-proxy.md)).
- Отдавайте серверу отдельного пользователя ОС и каталог `logs/` с ограниченными правами.

## Логи и аудит

- `logs/raw/` — сырые HTTP-обмены (при `SSVC_RAW_LOG` ≠ `off`), по файлу на день (`YYYY-MM-DD.jsonl`).
- `logs/audit.jsonl` — кто, что и когда вызвал из опасного; одна строка JSON на событие.
- Скачанные журналы и файлы — в `logs/downloads/` (или в каталоге, указанном инструментом).

Каталог `logs/` должен быть смонтирован томом при работе в Docker, иначе данные пропадут при
пересоздании контейнера.
