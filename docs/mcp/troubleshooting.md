# Диагностика

## Сначала — два запроса

```bash
curl -s http://127.0.0.1:8080/healthz
curl -s -H "Authorization: Bearer $SSVC_MCP_TOKEN" http://127.0.0.1:8080/readyz
```

- `healthz` — процесс жив (токен не нужен). Если он не отвечает, сервер не запустился: смотрите
  `docker logs ssvc-mcp` или stderr процесса.
- `readyz` — контроллер доступен, логин и токен в порядке. Если `healthz` есть, а `readyz` нет —
  проблема в сети до контроллера, пароле или учётной записи.

## Коды ошибок

| Код | Что значит | Что делать |
|---|---|---|
| `unauthorized` | HTTP 401: нет или неверен Bearer-токен | передайте `Authorization: Bearer <SSVC_MCP_TOKEN>` |
| `forbidden` | HTTP 403: адрес, `Host` или `Origin` не разрешён | проверьте `SSVC_MCP_ALLOWED_HOSTS` и `SSVC_MCP_ALLOWED_CIDRS` |
| `device_unreachable` | нет TCP-соединения с контроллером | проверьте `SSVC_DEVICE_URL`, сеть, питание |
| `device_timeout` | контроллер не ответил за таймаут | увеличьте `SSVC_DEVICE_TIMEOUT_MS`, проверьте загрузку |
| `auth_failed` | контроллер отклонил логин/пароль | проверьте `SSVC_USER`/`SSVC_PASSWORD` |
| `auth_required` | нет или неверен Bearer-токен клиента | передайте `Authorization: Bearer <SSVC_MCP_TOKEN>` |
| `forbidden_admin_required` | учётка не admin | используйте admin: телеметрия и датчики только для него |
| `feature_unsupported` | функция есть в API, но не в этой сборке/прошивке | это не сбой: например, реле на GPIO-сборке |
| `guard_blocked` | предохранитель контроллера запретил действие | смотрите `block_reasons` в ответе; устраните причину |
| `validation_failed` | аргументы не прошли проверку | сверьтесь со схемой из `tools/list` |
| `partial_apply` | часть настроек применилась, часть нет | смотрите `accepted`/`ignored`; повторите только `ignored` |
| `busy` | устройство занято (идёт передача журнала и т.п.) | повторите позже или отмените `oc_logs_cancel` |
| `queue_full` | очередь команд переполнена | дождитесь выполнения текущих команд |
| `not_found` | объект не найден (профиль, файл, запись журнала) | проверьте имя/путь |
| `confirmation_required` | операция риска 2/3 без `confirm:true` | добавьте `confirm:true` (для риска 3 — ещё `reason`) |
| `disabled_by_policy` | разрушительная операция запрещена | включите `SSVC_ALLOW_DESTRUCTIVE=1`, если это осознанно |
| `unsupported_operation` | операция не поддерживается сервером | проверьте имя инструмента и версию |
| `device_error` | контроллер вернул ошибку | в ответе есть HTTP-код и тело; смотрите `raw` при `debug:true` |
| `internal_error` | ошибка самого MCP-сервера | смотрите логи; при повторяемости — issue |

Ошибки приходят структурированно: `code`, русское `message`, `details`; для `guard_blocked` —
`block_reasons`, для `partial_apply` — списки применённых и пропущенных ключей.

## Известные ограничения

- **Реле на GPIO-сборке.** `oc_get_relay_*` и `oc_relay_override` возвращают `feature_unsupported`:
  в этой конфигурации реле нет. Это ожидаемо.
- **Журналы без SD-карты.** `oc_logs_list` вернёт `err_mnt` — журналы физически некуда писать.
- **Скачивание файлов на старых прошивках.** Если `GET /rest/files/{path}` отвечает деревом файлов,
  `oc_file_download` возвращает `feature_unsupported`. Обновите прошивку OpenConnect до версии с
  поддержкой скачивания файлов.
- **Неизвестные маршруты контроллера.** Прошивка может отвечать `200` с HTML-страницей вместо `404`;
  сервер распознаёт это и возвращает `not_found`, а не мусор в ответе.
- **Один контроллер.** Мультиустройство не поддерживается.
- **Разрушительные операции.** По умолчанию выключены — это защита, а не дефект.

## Логи

- Уровень: `SSVC_LOG_LEVEL=debug` (подробнее), `warn`/`error` (тише).
- Сырые обмены с контроллером: `SSVC_RAW_LOG=errors` или `all`, файлы в `SSVC_RAW_LOG_DIR`.
  **Только для отладки**: содержит данные контроллера, не оставляйте включённым.
- Аудит опасных операций: `SSVC_AUDIT_PATH` (JSONL). Проверить последние записи:

  ```bash
  tail -n 5 logs/audit.jsonl
  ```

- Диагностика изнутри: инструмент `oc_diagnostics` — версии, конфигурация (без секретов), сессии,
  состояние связи с устройством.

## Частые ситуации

**Клиент не подключается, сервер отвечает 401.** Токен клиента не совпадает с `SSVC_MCP_TOKEN` или
заголовок не передаётся (в конфигурации клиента проверьте `Authorization`).

**`host not allowed`.** При `SSVC_MCP_BIND=0.0.0.0` добавьте адрес, по которому подключаются, в
`SSVC_MCP_ALLOWED_HOSTS`.

**Клиенту нужен HTTPS, а сервер слушает HTTP.** Встроенный TLS по умолчанию выключен: поставьте
reverse-proxy ([reverse-proxy](../develop/reverse-proxy.md)) или задайте `SSVC_MCP_TLS_CERT`/`SSVC_MCP_TLS_KEY`.

**Ответ обрывается на большом журнале/файле.** Сервер отдаёт `Content-Length`, а не chunked; проверьте
лимиты прокси и `proxy_buffering`.

**После перезагрузки контроллера инструменты отвечают ошибкой.** Подождите 20–40 с: прошивка поднимает
сеть и UART; `readyz` вернётся в норму сам.

## Что приложить к обращению

Версию MCP-сервера (`oc_get_info`, `oc_diagnostics`), версию прошивки, код и текст ошибки, шаги до неё
и фрагмент лога без секретов.
