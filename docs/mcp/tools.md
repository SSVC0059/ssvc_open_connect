# Инструменты

Сервер предоставляет **51 инструмент**, 5 промптов и 2 ресурса. Имена стабильны: на них опираются
промпты и клиентские конфигурации.

## Классы риска

| Класс | Что означает | Что требуется |
|---|---|---|
| 0 | Чтение | ничего |
| 1 | Обратимая запись (настройки, зоны, пороги, профили-копии) | ничего |
| 2 | Влияет на процесс (старт/стоп, применение профиля, реле) | `confirm:true` |
| 3 | Разрушительно (удаление, перезагрузка) | `SSVC_ALLOW_DESTRUCTIVE=1`, `confirm:true`, `reason` |

Исключение — `oc_emergency_stop`: он не требует подтверждения, чтобы аварийная остановка не упиралась
в лишний шаг. Операции класса 3 по умолчанию возвращают `disabled_by_policy`.

## Информация и состояние

| Инструмент | Назначение |
|---|---|
| `oc_get_info` | Модель, версия прошивки, версия API, сборка |
| `oc_get_capabilities` | Какие функции поддерживает конкретная прошивка/сборка |
| `oc_diagnostics` | Диагностика самого MCP-сервера: конфиг, сессии, связь с устройством |
| `oc_get_state` | Полное состояние: стадия, фракции, флаги, тревоги |
| `oc_get_telemetry` | Телеметрия процесса: температуры, давление, отбор |
| `oc_get_process_status` | Краткий статус ректификации |
| `oc_wait_for_change` | Дождаться изменения стадии/статуса с таймаутом |

## Расчёт

| Инструмент | Назначение |
|---|---|
| `oc_calculate_plan` | План ректификации по входным данным: АС, фракции, скорости, таймеры, КПН. Без обращения к устройству |

Расчёт использует ту же модель, что калькулятор интерфейса. Это оценка с допущениями:
она не учитывает теплопотери, насадку и реальную мощность. Результат ничего не меняет на контроллере.

## Управление процессом

| Инструмент | Назначение |
|---|---|
| `oc_start` | Запустить ректификацию (проверяет предохранители устройства) |
| `oc_pause` / `oc_resume` | Пауза и продолжение отбора |
| `oc_next` | Перейти к следующей фракции |
| `oc_stop` | Остановить процесс |
| `oc_emergency_stop` | Аварийная остановка (без подтверждения) |
| `oc_send_command` | Служебная команда контроллеру (для нестандартных случаев) |

`oc_start` возвращает `commandId`; терминальное состояние — через `oc_wait_for_change` или
`oc_get_process_status`. Если устройство блокирует старт, ответ содержит `guard_blocked` и причины.

## Настройки, датчики, зоны

| Инструмент | Назначение |
|---|---|
| `oc_get_settings` / `oc_update_settings` | Действующие настройки SSVC |
| `oc_get_sensors` | Показания датчиков (DS18B20, BMP581 и др.) |
| `oc_get_zones` / `oc_set_zone` | Привязка датчиков к зонам |
| `oc_get_alarms` / `oc_set_alarm_thresholds` | Пороги тревог |

`oc_update_settings` меняет только переданные ключи; остальные остаются как были.

## Железо, реле, XKC-25

| Инструмент | Назначение |
|---|---|
| `oc_get_hardware_config` / `oc_update_hardware_config` | Аппаратная конфигурация |
| `oc_get_hardware_faults` | Аппаратные сбои (I²C, датчики, питание) |
| `oc_get_relay_metadata` / `oc_get_relay_state` | Метаданные и состояние реле |
| `oc_relay_override` | Ручное управление реле (класс 2) |
| `oc_get_xkc25_status` | Датчики уровня XKC-25 и их калибровка |
| `oc_xkc25_calibrate` | Запуск шага калибровки |
| `oc_xkc25_verify_status` | Результат проверки возврата |

На GPIO-сборках реле отсутствуют: инструменты вернут `feature_unsupported` — это корректный ответ,
а не ошибка сервера.

## Журналы, профили, файлы, система

| Инструмент | Назначение |
|---|---|
| `oc_logs_list` | Список журналов на контроллере |
| `oc_logs_download` | Скачать журнал в файл на сервере (бюджет 45 с) |
| `oc_logs_cancel` | Отменить передачу журнала |
| `oc_profiles_list` / `oc_profile_get` | Список и содержимое профилей |
| `oc_profile_create`, `oc_profile_copy`, `oc_profile_rename` | Создание, копия, переименование |
| `oc_profile_update_content` | Обновить содержимое (слияние верхних ключей) |
| `oc_profile_save_current` | Сохранить текущие настройки в профиль |
| `oc_profile_apply` / `oc_profile_delete` | Применить профиль (2) / удалить (3) |
| `oc_files_list` / `oc_file_download` | Дерево файлов и скачивание |
| `oc_file_copy` / `oc_file_delete` | Копирование (1) и удаление (3) |
| `oc_get_subsystems` / `oc_set_subsystem` | Состояние и переключение подсистем |
| `oc_system_status` / `oc_restart` | Состояние системы и перезагрузка (3) |

Журналы и файлы сохраняются **на сервере** (`logs/downloads/`), в контекст модели передаётся путь,
размер и краткая сводка.

## Ресурсы

- `openconnect://info` — сведения о контроллере и версиях;
- `openconnect://telemetry` — текущая телеметрия в JSON.

Ресурсы обновляются по запросу; клиент может подписаться на их чтение и перечитывать после изменений.

## Промпты

| Промпт | Сценарий |
|---|---|
| `start_rectification` | Подготовка и запуск ректификации с проверкой предохранителей |
| `troubleshoot_start_blocked` | Разбор причин, почему старт заблокирован |
| `calibrate_xkc25` | Пошаговая калибровка датчика уровня |
| `analyze_last_run` | Разбор последнего запуска по журналу и телеметрии |
| `apply_profile` | Выбор и применение профиля с подтверждением |

## Примеры вызовов

```json
{"name": "oc_get_telemetry", "arguments": {}}
{"name": "oc_start", "arguments": {"confirm": true}}
{"name": "oc_wait_for_change", "arguments": {"expect": {"stage": "<ожидаемая стадия>"}, "timeout_s": 60}}
{"name": "oc_logs_download", "arguments": {"process_id": 12}}
{"name": "oc_profile_apply", "arguments": {"id": "sugar", "confirm": true}}
{"name": "oc_restart", "arguments": {"confirm": true, "reason": "плановая перезагрузка"}}
```

Полные схемы аргументов клиент получает из `tools/list`; описания инструментов — на русском.
