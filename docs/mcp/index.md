# MCP-сервер OpenConnect

MCP-сервер превращает REST-интерфейс контроллера OpenConnect в **инструменты, ресурсы и промпты**,
которые понимает LLM-клиент (Claude Desktop, IDE-агенты, MCP Inspector и другие). Сервер работает
отдельным процессом рядом с контроллером и общается с ним по локальной сети.

```
MCP-клиент  ──HTTP(/mcp)──▶  MCP-сервер  ──HTTP(:80)──▶  контроллер OpenConnect
```

## Что можно делать

| Домен | Примеры |
|---|---|
| Состояние и телеметрия | текущая стадия, температура, давление, датчики, тревоги |
| Управление процессом | запуск, пауза, продолжение, следующая фракция, стоп, аварийный стоп |
| Настройки | чтение и изменение настроек SSVC, привязка датчиков к зонам, пороги тревог |
| Профили | список, чтение, создание, копирование, переименование, применение, удаление |
| Журналы | список журналов, скачивание CSV в файл на сервере |
| Файлы и железо | дерево файлов, скачивание, копирование, удаление; подсистемы; перезагрузка |
| Калибровка | датчики уровня XKC-25: статус, шаги калибровки, проверка возврата |

Всего — **51 инструмент**, 5 готовых промптов-сценариев и 2 ресурса с состоянием устройства.
Полный список — [Инструменты](tools.md).

## Что нужно

- контроллер OpenConnect в сети, доступный по HTTP (порт 80);
- учётная запись **admin** на контроллере (`/rest/telemetry` и `/rest/sensor` — только для админа);
- Node.js **≥ 22** либо Docker;
- прошивка OpenConnect с поддержкой `GET /rest/files/{path}`. На более старых прошивках
  всё работает, кроме `oc_file_download`: он честно ответит `feature_unsupported`.

## Быстрый старт

1. Создайте `.env` (образец — [`mcp/.env.example`](https://github.com/SSVC0059/ssvc_open_connect/blob/main/mcp/.env.example)):

   ```dotenv
   SSVC_DEVICE_URL=http://192.168.1.42
   SSVC_USER=admin
   SSVC_PASSWORD=ваш_пароль
   SSVC_MCP_TOKEN=сгенерируйте_openssl_rand_hex_32
   SSVC_MCP_BIND=0.0.0.0
   ```

2. Запустите контейнер:

   ```bash
   docker run -d --name ssvc-mcp -p 127.0.0.1:8080:8080 --env-file .env \
     -v "$PWD/logs:/app/logs" \
     ghcr.io/ssvc0059/ssvc_open_connect/mcp:1.0.0
   ```

3. Проверьте готовность:

   ```bash
   curl http://127.0.0.1:8080/healthz
   curl -H "Authorization: Bearer $SSVC_MCP_TOKEN" http://127.0.0.1:8080/readyz
   ```

4. Подключите клиент к `http://<host>:8080/mcp` с заголовком `Authorization: Bearer <токен>` —
   см. [Подключение клиентов](connect.md).

Другие способы установки (в том числе **из GitHub Release по ссылке**) — [Установка](install.md).

## Безопасность в двух словах

- клиенты обязаны присылать Bearer-токен; без него — `401`;
- по умолчанию разрешены только частные сети (`SSVC_MCP_ALLOWED_CIDRS=private`) и локальные `Host`;
- разрушительные операции (удаление, перезагрузка) **выключены** и требуют
  `SSVC_ALLOW_DESTRUCTIVE=1`, подтверждения `confirm:true` и причины `reason`;
- встроенного TLS нет: наружу — только через reverse-proxy с сертификатом
  (см. [Настройка](configuration.md) и [reverse-proxy](../develop/reverse-proxy.md)).

## Ограничения

- один контроллер на один экземпляр сервера;
- прошивка — единственный источник истины; сервер не хранит собственную модель процесса;
- на GPIO-сборках реле недоступны (`feature_unsupported`) — это данные, а не сбой;
- журналы требуют SD-карты на контроллере: без неё — `err_mnt`;
- журналы и файлы сохраняются на сервере, в контекст модели целиком не попадают.
