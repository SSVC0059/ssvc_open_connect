# Увеличение тестового покрытия SsvcSettings

По отчёту `npm run test:coverage:SsvcSettings` ниже — что именно не покрыто и какие тесты добавить.

## 1. Модалки: кнопка «Отменить»

**EditNumbersModal** (строки 93–94), **EditParallelV3** (49–51), **EditTimeModal** (179–180) — не покрыт сценарий «Отменить».

**Что сделать:** в тестах после открытия модалки вызывать клик по кнопке «Отменить» и проверять, что `onSave` не вызывался и модалка закрылась.

Пример (в любом тесте, где уже открывается модалка):

```ts
await userEvent.setup().click(within(dialog).getByRole('button', { name: /Отменить/i, hidden: true }));
await waitFor(() => expect(screen.queryByRole('dialog', { hidden: true })).not.toBeInTheDocument());
expect(mockOnSave).not.toHaveBeenCalled();
```

## 5. Ветки (Branch coverage 50–66%)

Низкий % Branch у компонентов часто из‑за условного рендера по настройкам:

- **SpeedSettings:** `{#if settings.late_heads}`, `{#if settings.tails}` — сейчас тесты используют мок с заполненными полями. Добавить тест с `createMockSsvcSettings()` без `late_heads` / с пустыми `tails`, чтобы секции не рендерились (покрыть ветку «нет секции»).
- **ParallelValve:** `{#if settings.parallel_v1}`, `{#if settings.parallel_v3}`, `{#if settings.parallel}` — аналогично: тесты с настройками, где часть этих полей отсутствует или пустая, чтобы проверить отсутствие соответствующих блоков.
- **ValveBandwidth:** `{#if settings.late_heads}`, `{#if settings.tails}` — то же самое.

Это поднимет именно Branch coverage.

## 6. Валидация в модалках

Сейчас тесты в основном сохраняют валидные значения. Не покрыты:

- ввод значения вне диапазона (min/max) — кнопка «Сохранить» disabled, подсказки об ошибке;
- в **EditTimeModal** — сообщение о кратности шагу и блокировка сохранения при неверном значении.

**Что сделать:** по одному тесту на модалку (например, EditNumbersModal в GeneralSettings): ввести число больше max (или меньше min), убедиться, что «Сохранить» недоступна и что после исправления сохранение проходит.

---

## 7. Не учитывать реестры в покрытии (опционально)

Файлы `tests/lib/*ExpectedRequests.ts` — по сути данные; низкий % по ним тянет общий отчёт вниз.

**Что сделать:** в `vite.config.ts` в секции `test.coverage` добавить:

```ts
coverage: {
  provider: 'v8',
  exclude: [
    '**/node_modules/**',
    '**/*.test.ts',
    '**/tests/lib/*ExpectedRequests.ts'
  ]
}
```

Тогда покрытие будет считаться только по коду приложения, а не по тестовым реестрам.
